# Multilingual Clip Pipeline

英語・インドネシア語の長時間動画から、日本語字幕付きクリップを制作するための
**工程管理・品質検査パイプラインの公開版**です。

実運用では、字幕の読速、表示時間、時刻ずれ、カット境界、成果物の同期などを
人の記憶だけに頼ると、同じ種類のミスが繰り返されました。
この公開版では、制作工程を一覧として表現し、字幕やカットの一部を検査します。
人による確認が必要な箇所を示しますが、人が実際に確認したことの証明や公開の制御は行いません。

> このリポジトリは、実運用システムから公開可能な設計だけを抽出したサニタイズ版です。
> 著作物、実際の動画、チャンネル運用データ、認証情報、タレント固有データは含みません。

## 30秒で分かる特徴

- **順序をコード化**: 分散していた工程と承認条件を、明示的なワークフローとして定義
- **失敗を早く見つける**: 読速、短すぎる字幕、カット外字幕、字幕・カットの重複を自動検出
- **確認工程を明示**: 承認フラグに応じて、最終工程を含む一覧を表示
- **再現可能**: 著作物を使わない合成JSON・合成動画・失敗例を含むテストを同梱
- **合成動画のE2E**: FFmpegでソース生成→2区間の切り出し→結合→尺検証まで実行
- **標準ライブラリ中心**: Python依存は標準ライブラリのみ。動画デモだけFFmpegを使用

## 背景と課題

個人で多言語動画の切り抜き制作を継続する中で、工程が複数のスクリプトへ分散し、
「どの順番で何を実行したか」が記憶頼みになりました。実際に、次のような問題が起きました。

- 字幕の表示時間を調整したあと、別工程が時刻を上書きした
- 確認用の仮動画を最終成果物として扱いかけた
- 字幕が読める速さか、カットの外へ出ていないかの確認が案件ごとに揺れた
- 機械検査が通っても、翻訳や演出の良し悪しまでは保証できなかった

その経験から、機械で検査できる条件と、人が内容を判断する必要がある工程を分けて考えました。
公開版では、その考え方の一部を検査と工程一覧で示しています。

例えば、実制作では、タレントがスケートボードについて話している回を探した経緯が
注釈に入り、視聴者には不要な制作側の情報になっていることに気づきました。
注釈とテロップの時系列一覧を要望して確認し、該当箇所の修正を依頼しました。
この判断は、文字数や表示時間を調べる機械検査だけでは代替できません。

複数人の会話では、声と字幕の対応や話者の取り違えも課題です。
[話者判別のケーススタディ](docs/speaker-diarization-case-study.md)では、私が行った聞き取りや制作上の判断、AIによる試作・検証とその限界を説明しています。話者判別機能はこの公開版には含まれていません。

## ワークフロー

以下は制作工程の概念図です。公開版が図の全工程を実行するわけではありません。

```text
構造化 → 時刻正規化 → 1080pプレビュー → 音声との照合 → 機械検査
                                                        ↓
                                                   人による通し確認
                                                        ↓ 承認後のみ
                                             最終書き出し → 情報同期
```

```bash
# 承認前の工程
clip-pipeline plan

# 承認済みと仮定した場合の工程一覧
clip-pipeline plan --approved-for-final
```

`plan` は工程を表示するコマンドです。フラグは利用者が指定するもので、プレビューの
確認や承認の事実を検証しません。公開版には最終書き出し・公開を制御する機能はなく、
`demo` は人の承認に依存せず合成動画を生成します。

## クイックスタート

```bash
git clone https://github.com/mIILAKA/multilingual-clip-pipeline.git
cd multilingual-clip-pipeline
python -m pip install -e ".[dev]"
python -m pytest -q
clip-pipeline validate examples/project.json
clip-pipeline plan
clip-pipeline demo
```

期待される結果:

```text
15 passed
OK: Synthetic multilingual clip — 検査項目に問題はありません
STOP: 最終書き出しには人の承認が必要です
OK: output/synthetic-demo.mp4 (15.00 秒)
```

`demo` はカラーバーと正弦波から32秒の合成ソースを作り、JSONで指定した2区間を
15秒のMP4へ結合します。実在の動画や音声はダウンロードしません。
生成先は指定した `--root` 配下の `media/` と `output/` に制限され、既存ファイルは
既定で上書きしません。デモを再生成するときだけ `clip-pipeline demo --force` を使います。

## 公開版で再現できる検査

| 検査 | 防ぐ問題 |
|---|---|
| 読速 | 画面に出ても読み切れない字幕 |
| 最短表示時間 | 一瞬だけ表示される字幕 |
| カット外字幕 | 採用していない場面に紐づく字幕 |
| 字幕重複 | 同じ表示領域で字幕が二重になる問題 |
| カット重複 | 同じ音声・映像が繰り返される問題 |

実運用版では、音声認識、語単位の時刻照合、FFmpegによるレンダリング、成果物のハッシュ同期なども扱います。
公開版では、第三者のコンテンツや個人の運用情報を必要とせず再現できるコアに絞っています。
字幕の翻訳品質や内容の正確さは判定しません。音声認識・話者判別・自動翻訳・
字幕の映像への焼き込みも公開版には含まれていません。

## E2Eデモで確認できること

```text
examples/project.json
        ↓ validate
media/synthetic-source.mp4       ← FFmpegのテストパターンだけで生成
        ↓ trim + concat
output/synthetic-demo.mp4        ← 320×180 / H.264 + AAC / 15.00秒
        ↓ ffprobe
期待尺との一致を確認
```

`media/` と `output/` はGit管理から除外されます。GitHub Actionsでも同じデモを実行し、
生成したMP4をCIアーティファクト（自動テストの成果物）として保存します。

## ディレクトリ構成

```text
src/clip_pipeline/
  models.py       # カット・字幕・検査結果のデータモデル
  validation.py   # 副作用のない品質検査
  workflow.py     # 承認フラグによって変わる工程一覧
  render.py       # 合成ソース生成・カット結合・尺取得
  cli.py          # validate / plan / demo コマンド
examples/
  project.json    # 著作物を含まない合成サンプル
tests/            # 正常系・複数の失敗系・工程一覧のテスト
docs/
  architecture.md # 設計判断と公開範囲
```

## AI支援開発について

設計・実装・テストにはAIコーディングエージェントを広く利用しています。
私は切り抜き制作で問題を見つけ、必要な確認方法や修正を伝え、成果物を利用・確認しました。
上の注釈の例は実制作での経験であり、この公開サンプル自体で実動画を検証した実績ではありません。
このリポジトリのコードが動くことと、私自身がすべてを独力で実装・説明できることは別です。
